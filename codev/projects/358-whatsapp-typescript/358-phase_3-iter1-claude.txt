DIFFERENCES FROM PYTHON (deliberate or unavoidable)
- fetch vs httpx: fetch has no per-phase timeouts, so each call has one overall deadline (5 s auth, 20 s Meta); chat streams use an idle timer that restarts on every chunk (60 s).
- fetch follows redirects unless told otherwise, so every call sets `redirect: 'manual'`; a redirect counts as a failure, as httpx's default does.
- One `MetaApiError` (with optional `status`) replaces httpx's two exception types.
- The mock apps/api client has no random latency or injected errors; the mock token is sha256-based, not a UUID.
- `readLines` splits only on \n, \r\n and \r (the SSE rule). Python's `splitlines` also splits on U+2028 and similar; this is intentional and tested.
- The "401 -> forget token, re-exchange once, retry once" flow is not in these clients. They raise `ApiUnauthorizedError`; the conversation manager (phase 4) does the retry.
- Errors are sent to Sentry through an injected `ErrorReporter`; the real Sentry sender is wired in phase 5. Until then the default is a no-op.
